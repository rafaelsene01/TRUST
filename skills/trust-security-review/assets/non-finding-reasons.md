# Non-Finding Reasons — Security Agent

> **Purpose:** standardized vocabulary for `reason_not_reported` in the Second Pass report.
> Use these categories and example phrases verbatim (or close to verbatim) so that
> the meta-reviewer can classify non-findings consistently across executions.
>
> **Rule:** every hunk without a finding MUST use one of the categories below.
> Inventing a free-form reason is allowed only when none of the 8 categories fit —
> and even then, state which category comes closest and why it doesn't apply.

---

## 1. Out of domain

The hunk belongs to a concern handled by a different TRUST agent (performance,
contracts, data model, conventions, tests). The security agent silently skips it.

**Example phrases:**
- `"Out of domain: changes are purely date formatting logic with no security-relevant surface (no input validation, no DB access, no auth)."`
- `"Out of domain: diff adds an index migration — performance concern only, no SEC-* rules apply."`

---

## 2. Confidence below threshold

The hunk contains a pattern that *might* violate a rule, but the agent's confidence
is < 0.80. The finding would be silenced by the Precision Gate anyway.

**Example phrases:**
- `"Confidence below threshold: the query builder method buildUserFilter may or may not use parameterization internally; confidence 0.65 is below the 0.80 minimum."`
- `"Confidence below threshold: the string 'sk-' prefix pattern in the constant name looks like an API key (SEC-001), but the value is a non-secret placeholder; confidence 0.72."`

---

## 3. Already reported

The same violation pattern — same rule, same file — was already emitted as a finding
in this run. The Second Pass must not double-count.

**Example phrases:**
- `"Already reported: the same SQL injection pattern (SEC-007) was emitted as a finding for src/auth/login.ts earlier in this run."`
- `"Already reported: SEC-002 (secret in log) was already reported for this file; this hunk is a second occurrence of the same variable."`

---

## 4. ADR exception

A project ADR explicitly exempts this pattern from the rule. The exemption must exist
in `grounding/07-adrs/` or be referenced in `06-security-policy.md`.

**Example phrases:**
- `"ADR exception: ADR-019 explicitly allows HTTP (non-HTTPS) for internal service-to-service calls on the private VPC. SEC-009 does not apply here."`
- `"ADR exception: ADR-031 permits MD5 for legacy checksum compatibility in the import pipeline. SEC-008 does not apply to this file."`

---

## 5. Test file

The hunk is in a test file. Most security rules (especially SEC-001, SEC-007) have
reduced scope in test files where mock credentials and synthetic queries are expected.

**Example phrases:**
- `"Test file: src/auth/__tests__/login.test.ts — hardcoded credentials are intentional test fixtures, not production secrets (SEC-001 out of scope for test files per 06-security-policy.md#test-exceptions)."`
- `"Test file: the SQL string is a static test fixture with no runtime execution. SEC-007 does not apply."`

---

## 6. Generated code

The file is produced by a code generator (protobuf, OpenAPI, ORM migrations auto-generated,
GraphQL codegen, etc.) and is not meant to be edited manually. The root issue, if any,
is in the generator template.

**Example phrases:**
- `"Generated code: src/generated/prisma/client.ts is auto-generated by Prisma CLI. Manual edits are overwritten on next generation; the rule applies to the schema source, not this output."`
- `"Generated code: the file header includes 'DO NOT EDIT — generated by openapi-generator'. Security rules must be applied to the template, not this artifact."`

---

## 7. Framework handles it

The framework or ORM used in this project automatically handles the security concern,
making a manual control redundant. Must be verifiable from the grounding docs.

**Example phrases:**
- `"Framework handles it: the project uses TypeORM's query builder (per 05-conventions.md#database), which parameterizes all inputs automatically. SEC-007 is satisfied by the framework."`
- `"Framework handles it: Express.js with helmet middleware (configured in app.ts) sets all required security headers. SEC-011 (CORS) is controlled centrally, not per-route."`

---

## 8. No relevant surface in file

The rule targets a specific technical surface (e.g. DB access, HTTP calls, auth checks)
that is genuinely absent from this file.

**Example phrases:**
- `"No relevant surface: src/utils/string-helpers.ts contains only pure string transformation functions with no DB access, external calls, or auth logic. SEC-007 through SEC-009 not applicable."`
- `"No relevant surface: the hunk modifies CSS styling constants. No security-relevant surface exists in this diff."`
